## 先搞清楚：日本 VPS 的「带宽」有两种，选错了很尴尬

雨云日本区的产品页上，同一档 CPU 和内存会给你两种计费模式：

- **大带宽限流量型**：带宽给得很大（最高到几百兆），但每月流量有配额。流量用完之后不会断网，而是被限速。
- **小带宽不限流量型**：带宽只有几兆到几十兆，但流量随便跑，不看配额。

限流量型用完流量后的处理方式两条线不一样：日本一区（极速三网）限速到 1M，日本二区（软银大带宽）限速到 5M，之后可以单独买流量包恢复高速。一区的流量包是 20G/20元、100G/100元、200G/180元；二区是 500G/50元、1024G/80元——单位价格差得挺多，二区的大流量包明显更划算。

还有个容易被忽略的细节：限流量型的剩余流量**每月自动叠加，次月不清零**。也就是说你这个月省下来的流量，下个月还能用。

**怎么选**：放网站、跑 API、远程办公这类流量不大但要求响应快的，选限流量型；做图床、跑下载、挂下载类应用、需要长时间稳定传输的，选不限流量型，否则超流量后 1M 的限速体验会很难受。

## 两条线路的真实差别：一个拼延迟，一个拼吞吐

**日本一区 · 极速三网**（三网直连）
- 去程走国内三大骨干网出口直连东京：电信 163 骨干网、联通 AS4837、移动 CMI。
- 回程按第三方测评的路由数据显示，电信走 CN2 GIA / CTGNet 精品线路、联通走 AS4837、移动走 CMI 经香港回境内。电信回程绕路少，这是它比普通日本机器 ping 低的主要原因。

**日本二区 · 软银大带宽**（软银线路）
- 去程三大骨干网对接 IIJ，回程三网统一走日本软银。
- 好处是带宽基数大、吞吐上限高；代价是国内访问延迟整体比一区高一些。

硬件平台用的是 AMD EPYC 系列（7K62/7A23 这类），配企业级 NVMe SSD，2 核机型跑 UnixBench 大概 1200–1300 分左右。这个成绩对建站、跑面板、做小规模业务是够的，别指望它去跑高并发数据库。

有个缺点得说清楚：**IP 是非原生 IP**。做普通建站、跑服务没影响，但如果你需要日本本土流媒体解锁或者特定地域业务，得先想清楚这一点。
